## Предлагаемые исправления (по приоритету)

**P0 — без этого нарушаем обязательные требования**
1. **R6 задержка связи как решение.** Минимальная версия: модуль **Weather Station** — в начале любого сола можно включить, он **съедает 1 единицу энергии каждый сол**, зато предупреждает о буре заранее (как на Луне). Без него на Марсе первый день бури — сюрприз: «радиосигнал с Земли идёт до ~20 минут, предупреждение не успело». Цена есть, решение есть, правда о задержке есть.

## Баланс после P0 (симуляция 1500–3000 прогонов, порт `ResourceModel` на Python)

| Стратегия | Победы |
|---|---|
| Фиксированная 3/2/2/3, без станции | 100% |
| Фиксированная + станция | 71% |
| Адаптивная (щит 5 в известные дни бури, иначе 1), без станции | 94% |
| Адаптивная + станция | 92% |
| Без щита / тяжёлый щит 3/2/4/1 | 0% (доза / наука) |

Вывод: решение о станции **есть и стоит энергию**, но сейчас **не выгодно**, а фиксированная стратегия всё ещё всегда выигрывает. Перебор только `baseDosePerSol` / `goal` / `doseLimit` / `reductionPerUnit` нужного режима не дал (лучшее: фиксированная 63%, адаптивная со станцией 26%) — нужна структурная правка в P1: например, буря без предупреждения сильнее (реальный пик 2.77× вместо среднего за сутки), щит набирается не мгновенно, или станция даёт ещё и бонус к науке. Цель прежняя: фиксированная < 50%, адаптивная > 80%.
